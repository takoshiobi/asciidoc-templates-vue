==== Fields Description
[cols="1,1,1,2", options="header"]
|===
| Field | Type | Required | Description 
| `event_id` | string (UUID) | Yes | Unique message identifier 
| `event_type` | string (enum) | Yes | Type of business event 
| `event_version` | int | Yes | Schema version 
| `created_at` | string (ISO 8601) | Yes | When event occurred in source system
| `source_system` | string | Yes | Which system produced this event 
| `correlation_id` | string (UUID) | Yes | End-to-end trace ID 
| `payload.payment_id` | string | Conditional* | Payment identifier 
| `payload.order_id` | string | Conditional* | Order identifier 
| `payload.customer_id` | string | Yes | Customer who performed action 
| `payload.amount` | decimal | Conditional* | Monetary amount 
| `payload.currency` | string | Conditional* | Currency code (ISO 4217) 
| `payload.payment_method` | string | Conditional* | How customer paid. 
|===

=== Business Logic 
. Verify `order_id` exists in `orders` table. If not → skip, log error (manual investigation required).
. Verify current order status is `AWAITING_PAYMENT`. If already `PAID` → skip as duplicate.
. Update order status from `AWAITING_PAYMENT` to `PAID`.
. Store payment details in `payments` table (`payment_id`, `amount`, `currency`, `payment_method`).
. Emit `order.paid` event to `order.events` topic.
. Send email confirmation to customer.
. Commit Kafka offset.

=== Error Handling & Retry Strategy
[cols="1,1,2", options="header"]
|===
| Error Type | Business impact | Our action
| Order not found | Cannot update status | Skip message, send to DLQ, alert manually (data inconsistency between systems)
| Validation failed (malformed payload) | Can't process event due to producer bug | Skip message, send to DLQ, alert producer team
| Duplicate message (by event_id) | No business impact | Skip silently, commit offset
|===
